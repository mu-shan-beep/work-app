# 个人工作台 Mac App · 第一版

## 直接使用

双击项目目录里的 `个人工作台.app` 即可。也可以把它拖到「应用程序」或固定到程序坞；不用运行终端、不用另装 Python、不用自己打开浏览器。界面沿用当前正在使用的工作台，未应用最近几张设计预览。

菜单栏「工作台」提供重新加载、打开数据目录和在浏览器中打开；常用复制粘贴和 Command+R / Command+Q 可用。关闭最后一个窗口即退出，退出前会提交当前文字草稿并停止 App 自己启动的服务。浏览器入口原有的服务不会被 App 停掉。

## 当前版本的分析

现在的工作台已经具备个人日常工作的主要功能：

| 模块 | 当前能力 | 实用性与剩余问题 |
| --- | --- | --- |
| 工作任务 | 新建、改名、分组、课时、下一步、关联目录 | 常用编辑可在桌面或圆环面板完成；复杂操作仍需要完整详情 |
| 产出与进度 | 分项四档状态、备注、需求份数、增删产出、全部完成 | 进度来自已完成项数，不是随意输入的百分比；部分完成的文件份数另算 |
| 任务分区 | 未完成／已完成、搜索、分组和状态筛选、自适应分页 | 能减少已完成任务干扰；大批任务处理仍缺少多选工具 |
| 今日安排 | 今日开关、独立分区、习惯入口 | 适合挑出少量今天要推进的任务 |
| 生活记录 | 习惯、历史补记、愿望、账单、金额日期修改 | 可作为轻量记录；不是完整记账系统 |
| 本地文件 | 系统选文件夹、打开目录、扫描产出 | 实际文件保留原位置；目录移动后需要重新关联 |
| 保存与恢复 | 本机 JSON、自动保存、删除后即时撤销 | 已删除记录保留在 `_trash`；独立回收站、导出导入和云同步尚未完成 |
| 界面 | 当前亮蓝导航、摘要统计、多色环、分页、动态效果 | 已比早期大页头紧凑；暂不继续改视觉，先保证工作连续性 |

综合判断：适合本机个人日常工作，也适合先打包使用；尚不是多设备协作产品。打包解决的是启动、窗口和运行环境，并不等于补齐云同步、备份和批量操作。

## 数据放在哪里

- 在这台 Mac 上，App 优先继续读写 `/Volumes/D/个人工作台/00-入口/` 的三个 JSON 文件。既有进度与目录关联不需要迁移。
- 页面代码和内置运行环境放在 App 内，业务记录不写进 App。以后换新版应用不会用初始快照覆盖已有文件。
- 如果在另一台 Mac 上找不到原目录，会首次复制包内的记录快照到 `~/Library/Application Support/个人工作台/`，以后继续用该位置。原任务指向的实际文件夹不会自动搬过去。
- 在本机继续使用时请保留原数据目录；若移动整个项目，应先备份 JSON，确认 App 菜单「打开数据目录」指向正确位置。
- 压缩包包含本次打包时的记录快照，是个人使用包；它不是清空数据后的公开分发版。

## 平台与安装范围

本次产物为 Apple 芯片 Mac 的 arm64 本地版，最低系统声明为 macOS 14，在当前这台 Mac 上验证。Intel Mac 和 Windows 需要另外构建。应用采用本机临时签名，未做 Apple 开发者签名及公证；在其他 Mac 上可能需要通过系统正常的「仍要打开」流程确认来源。

App 约 32MB，压缩包约 20MB，运行环境已随包包含。所有界面资源本地加载；本地服务只监听 `127.0.0.1`，每次自动选择空闲端口，避免与浏览器版的 8765 端口冲突。

## 实际验证

在独立数据副本和真正的原生 WKWebView 窗口内验证了：新建、改名、加入今天、全部完成、重新打开、分区自动切换、下一步保存、空生活记录新建、账单切换、移除与撤销、退出前草稿保存。浏览器脚本错误为零。

随后验证了压缩包解压、带空格的新位置运行、只使用系统基础 PATH（不依赖外部 Python）、再次启动后读取原记录、退出后自有服务端口关闭，以及应用签名完整性。真实 JSON 文件在测试前后哈希一致。

证据位于 `output/mac-tests/native.json`、`relaunch.json` 及对应窗口截图。验证数据为测试副本，截图中的测试任务不代表你的真实记录。

## 构建与维护

源代码为 `desktop/App.swift`、`desktop/Icon.swift`、`desktop/build.py`。服务仅增加了独立数据目录、自动分配端口和就绪消息支持，浏览器版默认行为保持原样。Python 打包使用 PyInstaller 6.22.3；当前构建工具环境在 `/private/tmp/wb-app-build-env`，临时目录清理后需重新准备，并通过 `WB_BUILD_PYTHON` 指定相应 Python。

应用是页面与服务的打包快照：以后修改源项目界面，需要重新运行构建，才能更新 App 中的页面。原始数据与界面资源分开保存。

原生容器依据 Apple 的 [WKWebView](https://developer.apple.com/documentation/webkit/wkwebview) 和 [应用生命周期](https://developer.apple.com/documentation/appkit/nsapplicationdelegate) 接口实现。

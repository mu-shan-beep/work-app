## 第一版界面 · 2026-11-06

保留通栏标题、横向页签和四项统计；任务区已改成紧凑桌面图标。桌面每行自动排列多个图标，手机每行三个，单击或按 Enter 打开详情弹窗。工作进度、工作分组和今日任务按窗口大小自动分页，点击底部分页按钮切换，桌面本身不滚动。

- **工作进度**：默认首页。搜索、按分组与状态筛选；筛选后回到第一页，关闭详情保持原页；每个入口使用放大的环形进度图，圆心显示完成百分比和已完成项数，下面显示任务名、当前待办产出和分组。点击图标弹出任务详情，在里面推进产出状态、写备注、填下一步、归类、编辑或打开文件夹。点关闭、空白遮罩或按 Esc 回到桌面；右键图标保留任务快捷菜单。
- **今日安排**：自己挑选今日任务，不自动替你决定优先级；下方是习惯打卡。
- **生活清单**：按分组展示习惯、账单和愿望，桌面四列卡片，支持搜索、筛选和直接记录。生活记录不计入工作完成度。
- **我的**：新建或设置工作／生活分组，调整默认产出，按文件手动同步。

打开页面只读取数据，不再自动扫描文件。主动同步会更新文件份数，并把文件已齐备、原状态为「未开始」的产出标为完成；其他人工状态沿用。

完成度按已完成的产出**项数**计算，文件份数单独显示。所有数字取自本地数据，没有加入设计稿里的示例任务。

### 任务模板与批量新建

同一类型的任务反复录入时，用「任务模板」把常填的几项预存下来。模板不是第二套产出规则，只是新建前的一层预填。

- **入口**：新建任务弹窗顶部的「套用模板」下拉；「我的 → 任务模板」集中管理，点模板条目可直接用它新建。
- **模板保存什么**：名称、所属分组、课时、父目录、下一步，以及可选的产出清单。
- **产出清单默认跟随分组**：与分组默认一致时不写入，以后改分组会自动同步；改动任意一项后才成为该模板专属，只作用于套用它的新任务，不影响已有任务和分组设置。表单里提供「沿用分组默认」一键还原。
- **不再提供批量新建**：一次建一条，避免一次批量建出几十条对不上号的记录。
- **父目录**按名称在同级目录（含一层子目录，例如 `已发布/颐和园`）寻找同名文件夹并自动关联；找不到就留空，建完再补。「从文件夹创建」仍保留系统目录选择。
- **顺手存成模板**：新建时勾「保存为模板」，会把这次的分组、课时、父目录、下一步和当前生效的产出清单一起存入模板；名称默认取任务名（批量时取「分组 · N 课时」），可改。同名同分组的模板会更新而不是新建一条，不会越存越多。
- 数据存在 `templates.json` 的 `presets` 数组里，不写进 `tasks.json`，不改变已有任务。

验证在独立数据副本中完成：模板增删改、套用预填（分组／课时／父目录／下一步）、产出清单覆盖与还原、从新建弹窗进入模板表单保存后返回并自动选中；勾「保存为模板」建任务后模板落盘、同名再存变为更新。布局实测（同一弹窗内）：分组与课时、父目录与「选择」两行的控件顶部同为 401、底部同为 521、右边缘同为 880/992，四个控件高度统一 38px。真实 21 个任务与 8 条泳道未改动，页面脚本错误为零。

### 界面热更新

改界面之后不必再重新打包 App。

- **取哪份文件**：服务端启动时先看数据目录（本机即 `00-入口`）里有没有 `app.html`，有就把它当界面根；没有才回退到 App 包内的副本。静态文件、`assets`、`native_folder_picker.js` 走同一套解析。
- **自动刷新**：页面每 2.5 秒比对一次界面指纹（`app.html`、`workbench.js`、`workbench.css`、`studio.css`、`shortcuts.js`、`native_folder_picker.js` 的修改时间与大小）。任一份改动就自动重载，并停在当前页面。
- **不打断输入**：弹窗打开或有输入框聚焦时，只弹「界面已更新 · 立即刷新」提示条；关掉弹窗后自动刷新，已填内容不会丢。
- **包内快照自动停用**：拿不到外部源码时（换机器、数据目录改到别处），页面用 App 内置副本，指纹不会变，轮询自行停止，不产生多余请求。
- **服务端仍要重新打包**：`server.py` 编译在 App 内，改它得重跑 `desktop/build.py`；界面层不受此限。
- 「我的 → 界面更新」显示当前界面来源目录，并提供「重新加载」按钮。

接口：`GET /api/webinfo` 返回 `{base, external, bundled, stamp}`；`/api/state` 同时带出 `web` 字段。

构建脚本相应调整：旧的 `output/mac-build` 与旧 App 先改名为 `output/.build-stale`／`output/.app-stale` 再重建，成功后才清理，不再用 `PyInstaller --clean` 原地删除大批文件。

### 应用自动更新

界面层靠热更新，App 本体（`server.py`、Swift 外壳）靠它自己换自己。

- **清单**：`desktop/build.py` 每次打包在 `output/mac/` 同时写出 `update.json`，含版本号、build、zip 文件名、sha256、体积、更新说明。zip 名改成纯 ASCII 的 `Workbench-Mac-arm64.zip`（GitHub 下载地址里带中文要转义，容易踩坑）。
- **检查**：App 启动后 3 秒自动检查一次（可在「设置 → 关于 → 自动更新」关闭），顶部菜单「个人工作台 → 检查更新…」可随时手动触发。比较的是 build 号，不是版本字符串。
- **替换**：确认后下载到临时目录 → 校验 sha256 → `ditto` 解压 → 确认新包里 `Info.plist` 与可执行文件完好 → 写一个独立 shell 脚本 → App 退出 → 脚本把旧包挪开、新包放回原位、去掉隔离属性、签名失效时重新 ad-hoc 签名、再 `open` 新版本。旧版进废纸篓，临时目录自动清理；替换失败会把旧版放回去。
- **数据不受影响**：只换 `个人工作台.app`，`00-入口` 里的三个 JSON 原地不动。
- **更新源（GitHub）**：`build.py` 把 `https://api.github.com/repos/mu-shan-beep/work-app/releases/latest` 写进 `workspace.json` 的 `updateFeed`。设置里也可以直接填 `github:owner/repo` 简写。**必须走 api.github.com，不要用 github.com**——本机直连 `github.com` 会超时（实测 25 秒无响应），`api.github.com`、`objects.githubusercontent.com`、`uploads.github.com` 都正常。所以更新器读的是 Release JSON，再从 `assets[].url` 取 `update.json` 和安装包（`Accept: application/octet-stream`），`update.json` 里的 `assetId` 就是安装包的资产编号。私有仓库再加 `updateToken` 字段（公开仓库不用）。
- **发版**：`WB_BUNDLE_PERSONAL_DATA=0` 打包（种子用 `defaults/`，不含真实任务）→ `GH_TOKEN=… python3 desktop/publish.py` 把 `update.json` + zip 传到 Release。`python3 desktop/publish.py --check` 只看线上最新版。token 也可以放 `~/.workbuddy/github-token`。`publish.py` 会先看包里有没有真实任务数据，有就拒发。

验证：用 1.3.0 的 App 副本跑一次真实升级，自动下载、校验、替换 `/tmp/wb-old/个人工作台.app`，重启后版本变为 1.3.1（build 6），进程从新路径拉起；同版本再跑一次只报「已是最新版本」，不做任何替换。

接口：`GET /api/webinfo` 另附 `bundled`；更新相关不使用服务端接口，全部在 App 内完成。
